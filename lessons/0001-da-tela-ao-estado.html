Da tela ao estado

Seu primeiro modelo mental para avaliar a stack sem precisar ler detalhes do código.

8–10 minutosSem pré-requisitos3 exercícios

A ideia central

As tecnologias não competem pelo mesmo trabalho. Elas formam um sistema em que cada uma protege ou executa uma responsabilidade diferente.

Regra de revisão: antes de perguntar “o código está certo?”, pergunte “esta responsabilidade está na camada certa?”.

O elenco, sem jargão

Interface

Vue 3

Monta a tela a partir dos dados atuais e reage a cliques, digitação e outras interações.

Contratos

TypeScript

Confere antecipadamente se as peças usam formatos compatíveis. Ele não desenha a tela.

Estado compartilhado

Pinia

Guarda os dados da sessão e centraliza as regras que descrevem como eles mudam.

Oficina

Vite

Mantém o desenvolvimento rápido e prepara o pacote que será publicado. Não decide regras do produto.

Aparência

Tailwind CSS

Expressa espaçamento, cores, tamanhos, alinhamento e comportamento responsivo.

Peças de interface

shadcn-vue + Reka UI

Entrega componentes Vue como diálogo, botão e tabela diretamente ao projeto; Reka UI sustenta os comportamentos acessíveis.

Essa separação acompanha as descrições oficiais: Vue organiza componentes e reatividade; TypeScript verifica tipos antes da execução; Vite serve e gera o projeto; Pinia gerencia estado compartilhado; Tailwind compõe estilos com utilitários; e shadcn-vue adiciona o código dos componentes ao próprio projeto.

Uma ação atravessando o Grana

Imagine que você cria uma transação. O fluxo atual acontece inteiramente no navegador:

Você clica

O botão do shadcn-vue, posicionado e estilizado com Tailwind, entrega o evento ao Vue.

Vue abre o formulário

O componente apresenta o diálogo e mantém os campos temporários enquanto você digita.

Uma ação é chamada

Ao salvar, o componente chama uma action da store Pinia com o novo rascunho.

Pinia altera a sessão

A store produz o novo estado em memória. Ainda não existe banco nem backend.

Vue redesenha

Ao perceber o novo estado reativo, Vue atualiza a parte necessária e a tabela ganha uma linha.

Recarregar reinicia

A página cria uma nova store com as fixtures originais. Por isso a alteração desaparece.

E o Vite? Ele possibilita que esse código chegue ao navegador, mas não participa da decisão de adicionar a transação. E o TypeScript? Ele verifica o encaixe das peças antes desse fluxo executar.

Prática de recuperação

Responda sem voltar ao diagrama. Errar aqui é útil: o feedback imediato fortalece a distinção entre as camadas.

Quem guarda a lista compartilhada de transações durante a sessão?

Quem expressa principalmente espaçamento e responsividade?

Quem detecta formatos incompatíveis antes da execução?

Como avaliar o próximo agente

  • Se ele alterar comportamento de dados apenas com classes Tailwind, peça para explicar.
  • Se guardar em um componente algo que várias telas precisam compartilhar, pergunte por que não está no estado compartilhado.
  • Se adicionar uma biblioteca para algo que shadcn-vue já oferece, peça a justificativa do novo custo.
  • Se disser que uma mudança é “do Vite”, confirme se ela trata realmente de desenvolvimento ou build.

Leitura primária

Leia apenas a introdução do guia oficial do Vue, até “Single-File Components”. A meta não é aprender código: é confirmar, na fonte oficial, como uma aplicação Vue organiza peças de interface.

Terminou? Conte ao agente, sem consultar a página, o caminho de uma nova transação do clique até a tabela. Pergunte imediatamente sobre qualquer parte que ainda pareça nebulosa.
